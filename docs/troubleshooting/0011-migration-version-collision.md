# 0011. 여러 PR이 같은 마이그레이션 번호를 가져가 겹침(V3·V4·V5)

- 기록: 2026-10-20
- 관련: 이슈 #10·#11·#6, PR #107·#109·#113·#108
- 상태: 해결(#113과의 번호는 병합 순서 협의 필요)

## 증상
- #108(최고 관리자 초기 등록)이 `V3__create_admin_account.sql`을 써서 #10의 `V3__create_zone.sql`과 번호가 겹쳤다.
- zone을 V4로 바꾸자 #11의 `V4__create_camera.sql`이 겹쳤다.
- camera를 V5로 바꾼 뒤, #6의 PR #113이 `V5__create_work_history.sql`을 쓰는 것이 확인됐다.

## 원인
여러 PR이 같은 시점에 "다음 번호"를 가져갔고, 병합 순서가 정해져 있지 않았다. 같은 버전이 둘이면 Flyway가 시작 단계에서 실패한다.
스택 PR이라 앞 PR의 번호 변경이 뒤 PR에 연쇄로 이어졌다.

## 해결
- zone: V3 → V4, camera: V4 → V5로 이름을 바꿨다. 리뷰어가 요청했고, 병합이 먼저 되는 #108이 V3을 가진다.
- #113(work_history)의 V5와는 아직 겹친다. 병합 순서를 정해 나중에 병합되는 쪽이 번호를 올려야 한다(예: #113을 V6으로).

## 재발 방지
PR을 올리기 직전과 병합 직전에 dev의 마지막 번호를 다시 확인한다. 열린 PR의 마이그레이션 번호를 표로 모아 병합 순서대로 부여하고, 바뀌면 관련 PR에 알린다.

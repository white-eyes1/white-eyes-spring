# 코드 해석본

이슈 작업에서 쓴 코드를 무엇을, 왜, 무엇을 염두에 두고 썼는지 줄·문단 단위로 설명한 사본이다. 원본 파일에 `// [해석]`(yml·env는 `# [해석]`) 주석과 맨 위 머리말만 덧붙였고, 코드 자체는 원본과 같다.

- 빌드·실행에 쓰이지 않는다. `src` 밖에 있어서 Gradle이 읽지 않는다.
- 원본과 해석본이 다르면 **원본이 맞다**. 해석본은 설명용이다.
- 파일 이름은 `원본이름(해석본).확장자`, 폴더 아래 경로는 원본 경로와 같다.

## 폴더
| 폴더 | 내용 |
|---|---|
| `shared/` | 여러 이슈 브랜치에 같은 내용으로 있는 파일(임시 Camera, 테스트 설정 등). 브랜치끼리 같은 내용으로 유지한다 |
| `issue-15/` | #15 FNC-A-025 캠 상태 보고 수신 |
| `issue-16/` | #16 FNC-A-024 분석 결과 수신 |
| `issue-17/` | #17 FNC-A-026 녹화 등록 수신 |
| `issue-18/` | #18 FNC-A-028 1분 통계 저장 (#16 브랜치 위에서 작업) |

## 고칠 때
- 원본을 바꾸면 해석본도 함께 고친다. `[해석]` 주석과 머리말을 걷어냈을 때 원본과 같아야 한다.
- `shared/`의 파일을 고치면 그 파일이 있는 다른 이슈 브랜치에도 같은 내용을 넣는다.
- 앞 이슈 브랜치 위에서 작업한 이슈(#18은 #16 위)가 앞 이슈의 파일을 고치면, 그 해석본은 새 폴더에 따로 두지 않고 앞 이슈 폴더의 것을 고친다. 머리말에 바꾼 이슈와 내용을 적는다.
- 임시 코드(`TODO(#10)`·`TODO(#11)`·`TODO(#13)`)를 정식 코드로 바꾸면 해당 해석본도 고치거나 지운다.
